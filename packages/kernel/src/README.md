# packages/core/src

This folder is for common abstractions. This is a light weight abstraction library that covers the major domain objects that the modules use to talk to each other with and the ways those objects are serialized.

Ideally each module should be self contained but it should have a few major shared domain objects that it can use to communicate with neighboring modules. This is where those shared modules go. If we're drawing the boundaries on our modules correctly we should be able to read the list of domain objects here like it's a high level glossary of the project. Each module can contain a bunch of hyper specific details, but the big picture shapes should be here.

Core should contain some IO/output adapter/serilizer code for just the core objects. The theory behind it is based in context reduction (both human and llm). If I need to update a serializer in a module then I can be sure that I can do it freely without worrying about other modules using it. If I have to update a serializer in the core module, then I can be sure that someone else in a different module is using it and that should kick off an investigation to see how those other users would be effected. 

Example, if I want to alter the a Trace file I know thats core to the project. Those changes are going to have to be reflected in how Go and Python classes write the persistence format as well as how each module that uses Trace loads it out of storage. If I'm just changing how python recorder reads pytest files then those serializers are kept outside of core where I can be sure that no one else is using it and I can be free to change it without investigation.

Don't think of core as a strict architectural zone. Core has a core, but core also has adapters in and out of itself. Other modules should depend on common things in core instead of depending on eachother directly.
